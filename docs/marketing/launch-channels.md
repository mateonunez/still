# Still launch channel plan

2026-10-07. No HN/Product Hunt/hub submission has been made. Current delivery is public source plus an experimental ad-hoc preview. Channel rules and exact artifact availability must be rechecked before launch.

## Now: improve the path people arrive at

Keep one canonical product URL, a direct release/build path, preview limits, real native visuals and a first-use/feedback guide. Curate GitHub metadata and actionable issues. Existing blog/X content can point to actual work, but do not announce an unfinished remote marketplace as launched.

The public repository should make these questions easy: What is it? Can I try it? What are its limits? How do I build a compatible plugin? How do I report a useful problem? These outcomes matter more than a star request.

## Show HN: technical preview after installation evidence

Fit: native macOS engineering, declarative extension contracts and a working experiment people can try. Before submission, confirm the exact preview/build instructions on a clean Mac and be available for technical discussion.

Prepare a factual maker brief: product purpose, OS-security distinction, supported/tested setup, exact artifact and source URLs, known transition/installation limits, extension design and useful feedback questions. Do not create ready-to-post HN prose. HN prohibits generated/AI-edited text and automated posting; the maker writes and manually submits/comments. Do not solicit votes or comments.

## Product Hunt: prepare now, coordinate a usable launch

Fit: visual personalization and a simple native Mac utility. Broad consumer acquisition should follow reliable install and first-use. Prefer a signed/notarized artifact for that audience; this is a Still UX recommendation, not a claimed platform requirement.

Prepare a personal maker draft, square product thumbnail, two real gallery screens, short native recording and concise launch copy. Keep installation, optional data access and the visual-security boundary readable. Check current field/image requirements in the official guide before upload. A third-party hunter is not required. Never ask for upvotes.

Lead with the calm-screen outcome; explain plugins as customization. Do not lead with six SDK terms or the planned npm command. Show source/SDK as a developer path. Launch copy must reflect the downloadable release, not a newer local candidate.

## GitHub: ongoing discovery

Use accurate topics, source/build examples, screenshot provenance, license and meaningful contributor issues. There is no verified submission route to Trending; treat a possible appearance as an outcome. No bought/coordinated stars, ranking formula or placement promise.

## Other hubs: individual fit

Evaluate Mac utility communities for everyday use and developer communities for a working plugin tutorial. Read each community's rules and participation expectations before posting. Prefer a useful walkthrough or technical contribution over repeated launch copy. This phase makes no claims about unresearched submission requirements.
