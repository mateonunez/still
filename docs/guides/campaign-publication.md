# Publishing a Still preview announcement

Use [the campaign plan](../marketing/campaign-plan.md), [launch copy](../marketing/launch-kit.md) and [blog introduction](../marketing/blog-introduction.md). Check the release version and download notes immediately before publication.

1. Verify the destination account belongs to the author. Use an authenticated personal browser session or the personal website repository.
2. Select the asset and describe its provenance. Conceptual art, diagnostic native view exports and recorded interactions are distinct.
3. Include an experimental-preview boundary and a link to installation notes. Do not claim notarization or untested compatibility.
4. Read the community rules before a new hub submission. Adapt the post to the audience and remain available for questions.
5. Verify the published result and save its URL and publication date in the campaign record. Track useful feedback through GitHub issues.

Do not expose private source data in recordings. Do not promise a release date or support matrix that has not been established. Scheduled publication requires a configured scheduling mechanism; a draft calendar alone does not schedule posts.
