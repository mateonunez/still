# Preview feedback

Start with [the first-use guide](https://meet-still.app/start). Use the GitHub [preview experience form](https://github.com/mateonunez/still/issues/new?template=preview-feedback.yml) for successful installations, blocked installations or usability feedback. Use Bug report for a focused reproduction, or Product or plugin idea for a proposed change.

Record release version, macOS version, architecture and actual observations. Describe connected displays when relevant. State which checks were not tested. A successful launch does not establish desktop privacy, authentication recovery or prolonged awake behavior.

Reports are public. Exclude credentials, client logs, conversations, calendar titles and private desktop screenshots. A sanitized reproduction is usually more useful than a raw log. No account data is required.

Triage product failures before expanding the collection: installation/recovery, unintended desktop exposure, source/permission reliability, native interaction and accessibility, then theme/plugin polish. Associate each fix with a reproduction and an acceptance check; do not mark unobserved hardware cases passing.
