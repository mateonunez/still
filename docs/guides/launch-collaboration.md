# Launch collaboration: evidence before reach

Prepared 2026-10-07. Use alongside the [delivery audit](../verification/delivery-and-channel-audit.md). These are preparation and joint trials, not published submissions or a scheduled campaign.

## 1. Align the next preview and test installation

The public download is preview.2; the refined editor is currently local/source-only. Prepare the next semantic experimental preview with explicit changes/known limits, and verify its exact packaged artifact before updating website links. Do not replace published assets in place. Developer ID/notarization remains a separate final beta gate.

On a second Mac or clean user environment, record macOS/architecture, download/checksum, extraction/first launch, menu discovery, Settings, a simple source, editing and authenticated return. Record denied permission, cancellation and recovery as separate results. Do not weaken global Gatekeeper protections. A compiler/deep-signature pass cannot replace this trial.

Engineering preparation: package/version/checksum/release notes and structured feedback. Maker contribution: access to the test environment, actual native trial and observed blockers. Acceptance: someone following the public instructions can run the exact build and report a reproducible result.

## 2. Record a real short demonstration

Use a clean desktop and non-private source data. Capture Porcelain → Glass, Free movement across a guide, resize with wrapped text, Grid destination/drop and saved reopening. A clock-only scene is sufficient. Avoid account identifiers, private quotas, event titles, project names and other open windows. Authentication/gesture/endurance claims require their own trials; the demo need not include a credential dialog.

Maker contribution: perform and review the actual interaction capture. Engineering preparation: trim, captions/transcript, optimized web/social variants and correct release labeling. Keep existing exported-image artwork labeled as such. Acceptance: a viewer can recognize what changes and try that same published artifact.

## 3. r/macapps: focused user feedback

Purpose: discover installation, native-feel, screen-layout and source-configuration problems. Prepare problem/comparison/pricing facts, free/MIT/preview status, official download, known visual-security limits and one genuine recording.

Maker contribution: verify the personal account's local karma, promotion history, current eligibility and Read the Rules/post-approval flow. Main-feed eligibility is not assumed; use the designated megathread when appropriate. Do not obtain karma through manufactured engagement. [Current rules](https://www.reddit.com/r/macapps/about/rules/), [approval](https://www.reddit.com/r/macapps/comments/1smg62t/how_to_gain_post_approval_in_rmacapps_with_read/).

Engineering preparation: evidence/assets and reusable issue-report instructions. Desired result: actionable reports, not votes. AI/automation policy and account eligibility must be verified before using generated posting material.

## 4. Swift Forums: invite technical collaboration

Purpose: share the MIT native work and invite contributions to one concrete mechanism. Use [Community Showcase](https://forums.swift.org/c/community-showcase/66) for an announcement. A focused implementation question should include a reproduction rather than disguised promotion.

Useful facts: geometry is display-local; Free guide thresholds previously caused 6.5-point jumps for a 0.5-point pointer increment; regression tests now preserve pointer continuity; Grid commits at drop; dense collision settling still needs interaction work.

A reproducible source command on macOS:

```sh
swift test --package-path packages/StillNativePlugins --filter alignmentGuidesDoNotJumpAsPointerCrossesTheirThreshold
```

[Geometry code](../../packages/StillNativePlugins/Sources/StillNativePlugins/CanvasAlignment.swift) · [Regression](../../packages/StillNativePlugins/Tests/StillNativePluginsTests/CanvasAlignmentTests.swift) · [Editor issue](https://github.com/mateonunez/still/issues/1).

Engineering preparation: source references, minimal example and observed limitation. Maker contribution: select a genuine technical question, review the description, confirm personal forum access and discuss tradeoffs. Specific AI/automated-post policy remains unverified; preparation is not publication permission.

## 5. Personal blog → Hashnode: one useful engineering article

Proposed topic: pointer continuity in a native canvas, or separating package installation from source permission. Teach a reusable mechanism with actual code/results; do not announce the unfinished repository installer as available.

Engineering preparation: tested examples, references, outline, draft and diagrams. Maker contribution: firsthand review, accurate author/disclosure choices and substantive discussion. Publish the original on the personal blog; manually republish one article on Hashnode with the canonical Original URL. [Conduct](https://hashnode.com/code-of-conduct), [editor](https://docs.hashnode.com/blogs/editor/writing-a-blog-post).

DEV is conditional because its linked AI guidelines restrict promotional AI-assisted articles and generated replies. Do not send the same launch copy across technical communities.
